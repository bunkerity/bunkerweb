The caller owns the styling and sets, before the include: `pill_ul_class`, `pill_first_li_class`, `pill_icon_size`, `pill_label_class`. Reads `pane_blueprint` and `mode` from the caller's context. ================ WHY /services AND /global-settings NAVIGATE INSTEAD OF TABBING ================ On those two pages the pills are LINKS, not `data-bs-toggle="tab"` buttons, and that is the whole point of S3.5 rather than a styling choice. Compose and Raw are two views of the SAME configuration, and a client-side tab switch showed the raw editor exactly as the server rendered it at page load -- so unsaved compose edits were invisible there, and saving from raw silently wrote the stale twin back over them. Navigating re-renders BOTH panes from the database, which makes a stale twin impossible by construction instead of by a merge routine that has to be kept correct. It also repairs the pane/branch disagreement T7 opened. `mode` is a query argument, not a route segment; the monolith's `handleModeChange` kept it in sync with `history.pushState`, and that machinery died with the pane switcher. From then on Raw changed no URL, the raw editor's synthetic form posts to `window.location.href` (js/pages/settings-raw.js:132), and `resolve_save_mode` therefore fell back to `easy` -- whose indiscriminate re-injection (routes/services.py, update_service) puts back every stored key the payload omitted, so DELETING A LINE IN THE RAW EDITOR became a silent no-op and the multisite `_` prefix strip never ran. An `href` carrying `?mode=raw` is what makes the pane the user is looking at and the branch the server runs the same fact. /templates/ keeps real tabs: `template_edit.html` renders `#navs-modes-easy` and `#navs-modes-raw` itself and switches between them client-side (js/pages/template_edit.js), with its own `view_mode` round-trip. Different feature, same chrome -- do not unify them. Query handling: both hrefs are built from `request.args` so `clone` and `type` survive a switch (dropping `clone` on /services/new silently creates an EMPTY service). They are RELATIVE -- `?a=b`, never `/services/...` -- because a hardcoded absolute path breaks when the UI is mounted behind REVERSE_PROXY_URL, and a misdirected request carries the `__Host-` session cookie with it.
