A plugin that gains a multisite setting appears here with no code change; `workflows` and the other eight plugins with zero multisite settings simply never enter the loop. ============================ THE SAVE CONTRACT ============================ A row renders enabled, postable inputs IFF `shelf_plugin_scope(...)` returns a non-empty set, and it then posts EVERY key in that set on EVERY save. `Database.save_config` deletes any in-scope key the form did not post (db_methods/config_save.py:592), so over-claiming destroys data while under-claiming merely preserves it. That biconditional is pinned over the REAL shipped manifests by tests/unit/ui/test_compose_shelf.py::test_row_posts_exactly_the_declared_scope. Consequences that look like details and are not: * Every postable element carries `data-shelf-post`. The keys a row posts are exactly `shelf_plugin_scope(...)` -- not the activation map, which also declares keys this surface deliberately cannot post (`multiple` / `multiselect`). * A switch is a NAMED checkbox and an unchecked checkbox posts NOTHING, so each one is immediately followed by a hidden input of the SAME name carrying the inactive value. `request.form.to_dict()` keeps the FIRST value for a repeated name, so checked wins and unchecked falls through. The fallback must stay adjacent to its own box: moving it to the end of the form would put it AFTER the control-key inputs below, and a switched-off `USE_UI` would then lose to the stale control value. * The checkbox's own `value` is the CURRENT value while the plugin is already active, so a save that touches nothing writes nothing new. Only a genuinely inactive plugin gets the canonical active value (the complement of the declared inactive one, or the single remaining legal `select` option). * Multi-key plugins (`limit` = USE_LIMIT_REQ + USE_LIMIT_CONN) render ONE switch: the first declared key is the checkbox, the siblings are hidden inputs at their current value that js/components/compose-shelf.js rewrites to the inactive value when the switch goes off. With JS disabled the siblings still post their current value -- an incomplete OFF, never a deleted row. * `multiple` / `multiselect` activation keys (redirect, country) get a count and a chevron and post NOTHING, which is why they are out of scope: `_in_scope` base-matches, so claiming REDIRECT_TO would drag every stored REDIRECT_TO_ into scope for a row that posts none of them. * Free-text activation keys (inject, php) get an OPENER, not a switch: `type`/`regex` admit every string, so no active value is derivable and the shelf must not invent one. They are OUT of scope (`shelf_plugin_scope` drops `text`), so the row posts nothing and owns nothing. Round-tripping their stored value to keep them in scope is worse than the deletion it avoids: CRLF + trim normalisation makes config_save materialise a real `ui` row and decouple the service from the global. Activating or clearing them happens on the plugin page. * Folded rows hide with `display:none` ONLY (see the JS).
