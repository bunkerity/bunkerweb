This file owns the LAYOUT and nothing else. ================== THE FACT THE FLAT FORM HID ================== `WHITELIST_COUNTRY` and `BLACKLIST_COUNTRY` are NOT two independent lists, and they are not ORed. `core/country/country.lua:131-160` processes the whitelist FIRST and returns from inside that branch either way: a country in the list is allowed, a country outside it is DENIED. The blacklist branch at :163 is only reached when `WHITELIST_COUNTRY` is empty. So setting a country whitelist is "allow only these and deny the rest", and it makes any stored country blacklist dead configuration -- which the generic grid rendered as two equal 250-option multiselects with nothing saying so. The picker below presents that as the one choice it actually is. It carries NO `name`: it is a client-side control, and an unnamed select is not serialised -- so the POST body stays exactly this plugin's own keys and no route has to learn to pop a form-only key. ======================= HIDE, NEVER OMIT ======================= Both country lists render on every load whatever the picker shows; the wrapper the picker turns off carries the `hidden` attribute, which suppresses rendering and nothing else, so the inputs inside still serialise. `postable_scope` claims all three keys and an in-scope key the POST does not carry has its row DELETED (db_methods/config_save.py:579-585) -- a body that rendered only the selected list would wipe the other one the first time the operator saved. Pinned by tests/unit/ui/test_plugin_settings_bodies.py::test_every_shipped_body_posts_exactly_the_declared_scope and ::test_the_country_body_posts_both_lists_in_every_mode.
