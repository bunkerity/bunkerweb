Every chip below it is nameless chrome that rewrites that one input, exactly the way models/multivalue_setting.html drives its own hidden input. That is not a stylistic choice: one stored key is one form field, so a term row cannot be a field of its own without inventing a second save path. It also makes the JS optional -- see below. ======================= HIDE, NEVER OMIT ======================= `postable_scope` walks the STORED config and base-matches (models/save_scope.py:99-110), so a stored `_RULE_2` is inside this page's declared scope by its own name, and an in-scope key the POST does not carry has its row DELETED (db_methods/config_save.py:579-585). Every suffix therefore renders on every load, collapsed or not -- `.multiple-collapse` hides with Bootstrap's `collapse`, which suppresses rendering only, so the input still serialises. Deleting a rule means the operator removes its group and the family posts WITHOUT that suffix; that is the same gesture (and the same shared handler) every other numeric-suffix family uses.
